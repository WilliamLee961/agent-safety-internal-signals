# 先确认真实问题的复现计划

状态：计划，尚未启动模型运行。首个复现对象是 AgentDyn 的正常任务与防御效用现象；不是先实现新 LCIC 方法。

## 阶段 0 公开轨迹与代码核查

运行 `scripts/audit_public_logs.py` 重查固定版本的四条公开记录。手工核对用户目标、认证返回、过滤标记、下一步动作和 evaluator。审计不消耗模型费用，也不等同于复现。

根据 AgentDyn 官方代码核查任务定义、合法认证条件、过滤器实现、阈值、模型输出到工具的接口和评价方式。记录代码提交与依赖版本；不静默修补后仍声称完全复现原设置。

## 阶段 1 最小重新运行

先在相同环境运行两条已有证据任务，分别比较无防御和 `transformers_pi_detector`。随后扩大到约 10–20 条用于调试与机制分析的正常任务，覆盖普通检索、合法外部流程和关键参数。该小样本不作为整体性能结论。

模型及资源尚未确定。若原模型快照不可用，记录替代模型并称“现象迁移验证”，不称原表的严格复现。先保持模型和环境一致，再扩展到有内部状态访问能力的开源模型。

AgentDyn README 中确认存在的官方运行入口示例（不是本项目已执行命令）：

```bash
python -m agentdojo.scripts.benchmark -s shopping \
    --model GPT_4O_2024_08_06 \
    --defense tool_filter --attack important_instructions
```

正式执行前先运行该版本的 `--help`，核实选择单任务、无攻击及无防御的参数。不要根据上述示例臆造 CLI 标志，也不要直接启动全量付费实验。

## 阶段 2 区分失败原因

为每次运行保存：任务与攻击位置、模型版本、历史、拟调用工具与参数、防御评分及理由、真实执行动作、环境状态、两个目标的评价、调用数/token/延迟、错误与超时。

人工复核分类：

- 无防御也不会做的能力失败。
- 工具、依赖、格式或 evaluator 错误。
- 合法内容被过滤或合法动作被拦。
- 攻击被放行。
- 信息不足无法归因。

在沙箱状态下做成对干预：只恢复被过滤的合法信息、或只改变检查次数/格式/出现位置，尽量控制其他条件。根据随机性需要重复运行。不要在真实服务重复执行发送、支付或删除等动作。

## 阶段 3 检查近期强基线是否已解决

优先评估与假设最接近且代码可复现的 AttriGuard、AgentSentry；StepGuard 作为学习式步骤守卫对照。PACT、PIPES、EvoSafeHarness 用于进一步检查参数、输入边界和运行时设计的重叠。

公开代码、权重、模型接口和预算的可用性尚未全部核实。不能承诺所有方法都能原样运行。适配差异须披露，弱化移植不能代表原方法。

只有强方法仍留有可解释缺口，才进入新方法设计。仅恢复一个较弱过滤器的效用不等于形成充分创新。

## 阶段 4 验证内部信号

建立不使用内部信号的核验策略，再加入信号，并与相同额外调用预算的重复检查或固定阈值版本比较。冻结模型起步，测量特征提取的显存、token 与延迟成本；完整注意力可能改变推理实现和资源使用。

用 AgentDojo 作共同基准，AgentDyn 作动态流程互补，受控变体解释机制。按任务/模板/场景分割数据，验证集调参、测试集固定。加入未见场景与自适应攻击；报告 ASR、Clean Utility、Utility under Attack 和成本，遵循官方聚合方式。

## 继续或调整的条件

继续：有稳定且可定位的残余误干预；简单调阈值不足以解决；新策略在同预算、相近安全水平下改善效用；内部特征有可消融的增益。

调整：主要瓶颈是底层模型能力、程序错误、旧攻击太弱或旧基线太弱；内部信号无增益；新机制与已有工作重叠。不得把这些情况包装成正向结果。

## 启动模型实验前需要的资源信息

GPU 与显存、可用模型或端点、可接受的运行费用/时长，以及是否能取得隐藏状态、注意力或 logits。这些信息当前未知。日志审计、文献筛选和代码准备可以独立继续。
